## 一、历史模型结构(见 `architecture.png`)

整体是 **双流输入 → 共享 trunk → 一个潜在严重度 `s` → 多任务有序阈值头**。

```
每个动作的片段(16帧/单图)
  ├─ 外观流:MARLIN(冻结的人脸视频自监督编码器) ───────────────┐
  └─ 几何流:MediaPipe(52 blendshape + 左右不对称) → GRU(可训练) ┤
                                                          拼接 concat
                                                              │ 每动作 MLP
                                                              ▼ → 动作池化
                                                       患者表示 h → 全局严重度 s(标量)
                                                              │
                          ┌───────────────────────────────────┼───────────────────┐
                          ▼(读同一个 s)                       ▼(自有区域严重度)
                 HB I–VI / 二分类 / 3级  有序阈值头        眼部 / 嘴部  区域头
```

逐模块说明:

1. **外观流 — MARLIN(冻结)**:ViT-Base 掩码自编码器,在 ~70 万人脸视频上自监督预训练。输入 16 帧对齐人脸 → 输出 768 维"外观+短时运动"向量。**冻结、不训练**,嵌入预先算好缓存。
2. **几何流 — MediaPipe → GRU(可训练)**:每帧提取 52 个 blendshape + 左右镜像对的不对称差值(共 72 维),组成逐帧序列;送入一个**可训练的双向 GRU**(带注意力池化),输出"动态向量"。这条流显式编码**左右不对称的运动轨迹**——面瘫最关键的诊断信号。
3. **拼接**:把外观向量(768)和动态向量拼成每个动作的 embedding。
4. **共享 trunk**:每动作 MLP → 动作池化(mean / 注意力)→ 患者表示 `h` → 投影出一个**标量全局严重度 `s`**。
5. **多任务有序阈值头(核心思想)**:不强行统一不同数据集的标签尺度,而是让所有任务共享同一个 `s`,每个数据集学一组**单调有序的切点**映射到自己的标签空间(HB 6 级 / 二分类 / 3 级)。区域任务(眼/嘴)从 `h` 投影出**自己的局部严重度**,不污染全局 `s`。序数损失用 CORAL 风格累积阈值,**秩一致性由构造保证**。

> 这一设计让"标签尺度不一致"的多个数据集可以**共同训练而不造假标签**。

## 二、数据预处理 —— 每一步处理

1. **按动作分段(分段在预处理,不在模型)**:把 ~2 分钟的提示式录像切成"每个动作一个 ~3 秒短片"。Mayo 无精确时间戳,但动作顺序固定(7–8 个),我们用**语音提示起点 + blendshape 动作签名**(抬眉→browUp、闭眼→eyeBlink、微笑→mouthSmile、撅嘴→mouthPucker、露下齿→mouthLowerDown)**按序识别**每个动作。图像是退化情形(等价于无运动的单帧)。
2. **人脸检测与裁剪对齐**:用 MediaPipe(或本地的 cv2 Haar 备用)定位人脸,裁成 224×224 对齐人脸。
3. **画质归一化(work_size=112)**:把分辨率上限统一(降采样→升采样),缩小"公开老旧模糊图 vs iPhone 高清"的域差;训练/推理用同一套,训练时可加抖动增强。
4. **MARLIN 外观编码**:每个动作采样 16 帧 → MARLIN → 768 维;一个片段若有多窗口则掩码均值池化。**冻结、缓存**。
5. **MediaPipe 几何特征**:逐帧 52 blendshape + 20 个左右不对称差值 = 72 维序列(`mp_seq`),带帧掩码。
6. **打包缓存为 bundle(.npz)**:每个患者/动作存 `marlin` + `mp_seq` + `mp_mask`,供模型直接读,避免重复编码。
7. **防数据泄露(关键)**:这些公开集是网络爬取、彼此有重复图。我们用感知哈希查重(`dedup_check.py`),**视频按患者划分、图片按重复组划分、跨数据集去重、网络集只进训练**(详见 `docs/leakage_policy.md`)。

## 三、训练阶段 —— 每个阶段 + 每项处理

整体策略:**迁移学习是脊梁**(临床数据极少,从零训不可能;只训几十万参数的小头)。

### Stage 0 — 冻结预训练编码器(无需临床数据)
- 外观编码器 MARLIN 冻结;MediaPipe 提取器也是预训练/固定。
- **唯一可训练的**只有:小的时序 GRU、共享 trunk、有序阈值头(合计几十万参数)。这正是 N≈20–60 也能训的原因。

### Stage 1 — 在全部公开数据上多任务有监督微调(塑造 `s`)
- 数据:PalsyNet(二分类)+ FNP / YFP(眼/嘴区域 3 级)等,经上面的预处理打包。
- **每项处理**:
  - **逐样本任务路由**:每个样本带 `(embedding, 任务名, 标签)`;一个 batch 可混多个数据集。模型对所有头都算输出,但**损失只监督该样本对应的头**;梯度经 `s`(全局任务)或区域投影(区域任务)回流共享 trunk。
  - **每任务损失权重**:平衡不同数据集规模。
  - **诚实留出评估**:PalsyNet 按患者分层留出;FNP 用自带 valid;YFP 留出若干患者。报告分任务、分来源指标(防止"按来源标签先验"作弊)。
  - 产出:历史 warm-start checkpoint(v1=均值池化 / v2=注意力池化 / v4=扩充数据)，不代表部署授权。
- **历史结果**:公开数据上 palsy 检测 AUC≈0.86、嘴部严重度 QWK≈0.86、眼部≈0.46(均为"方法验证",非临床数)。

### Stage 2 — HB 校准(等真实 HB 标签)⬅ 当前瓶颈
- 用 MEEI / Mayo 的真实 HB 标签训练/校准 HB 阈值头。**因为还没有 HB 标签,这一阶段尚未开始。**

### Stage 3 — 域适应(可选)
- 适配 Mayo iPhone 分布;少量 HB 标签主要用于"校准头",而非重训编码器。

### 已在 GPU 上跑通的相关处理(RunPod A100)
- 用**真实 MediaPipe** 提取了全部 Mayo 视频的几何特征(本地装不了 mediapipe);
- 按动作分段成功,模型第一次以"逐动作模式"在真实 Mayo 数据上运行(非坍缩);
- 自动化搜索(autoresearch)跑了 40 组配置,结论是**模型配置已到平台期,天花板是数据而非结构**。

## 四、可视化方法(给 PPT 用)

### A. 模型判断依据(可解释)——`decision_basis_<患者>.png`
我们已证明:模型学出来的 `s` 在 Mayo 域上主要读"外观/相机",而**真正可信、可解释的依据是"左右不对称"**。所以可解释图直接画**分区左右不对称**:
- **示意脸(facogram)**:额/眉、眼、嘴三区按其"左右不对称指数"上色(绿=对称/健康 → 红=重),并标出较弱的一侧;
- **逐动作不对称条形图**:哪个动作(抬眉/闭眼/微笑…)最不对称,一目了然。
- 例:`MySlate_29` 的图清楚显示——**抬眉极不对称(0.62,红),其余基本对称**,较弱侧为患者右。这就是"模型/评分凭什么判断他严重"的直接依据。

### B. 各患者总览 ——`facogram_panel.png`
所有患者 × 三个区域的不对称热力图,一眼看出每个人是额/眼/嘴哪个区域受累。

### C. 模型结构图 ——`architecture.png`
双流→共享 `s`→多任务头的整体示意(本说明第一节)。

> 这套不对称可解释图的好处:**无需标签、临床可解释("你的左脸微笑比右脸弱 40%")、且跨域稳健**——非常适合放进 PPT 讲"模型依据"。
